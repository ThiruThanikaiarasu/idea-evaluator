# Idea Evaluator

Use the project’s evaluator framework to help a person make a better next product decision. The framework is not a startup generator and must not present unverified market claims as facts.

## Intake

Collect or confirm these three inputs before evaluation:

1. A short title.
2. A concise description of the target user, problem, and proposed solution.
3. The submitter’s consent to analyse and, if relevant, show the idea.

Do not analyse ideas without consent. If the description is vague, ask one focused question before running the workflow.

## Workflow

1. Run an initial assessment for one concern, one promising angle, and a decision.
2. Run the four specialist reviewers: Skeptical CTO, Bored User, Competitor, and Honest Friend.
3. Keep the reviewers independent; they advise but do not make the decision.
4. Use the coordinator output to identify consensus risks, uncertainty, evidence gaps, and the first problem to solve.
5. Present the diagnosis to the person who submitted the idea. Ask whether they approve the direction or want to correct it.
6. Only after explicit approval, run the mentor stage to create the narrow MVP, two-weekend plan, exclusions, user-validation step, and success metric.

## Evidence and tone

- Label competitor, pricing, and market statements as hypotheses unless their sources are verified.
- Be direct but respectful. The objective is clarity, never public humiliation.
- Never claim the result proves demand. Real users outside the conversation validate demand.

## Output

Return a concise decision report with:

- decision: proceed, narrow, pivot, or stop;
- consensus risks and evidence gaps;
- smallest testable version;
- what not to build;
- one real-user validation activity; and
- one measurable success metric.

Close with: “This is not a startup. It is a better next action.”
